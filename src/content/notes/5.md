自从我开始搭建新的具身 Agent Harness 已经过去了两个多月，Coding Agent 维护的开发日志堆成了山，但我的工作好像还停留在起点。

Harness 的雏形很早就有了，随后我就陷入了底层算法、层次抽象、整体优化、文档构建的来回死磕，时不时想加个新机制却又虎头蛇尾。到最后项目到底有没有在进步连我自己都说不清。每次测试，我还在亲自运行 Harness、把各个可视化窗口拖到互不遮挡的位置、调一下仿真摄像机的视角、给 Agent 发指令、观察执行效果，失败了很难有什么启发，成功了好像也说明不了什么。

直到一个多月过后，我也不知是才想起来还是才做出决定，要搭一套能批量生成任务集、运行实验、统计指标的评测框架了。然而具身 Agent Harness 尚无通用评测框架，只能自建或深度改造，其评测难度与体量远大于基座运动模型，我还看中了变量更多更耦合的 RSI（递归自我改进）作为研究方向。

我最终构想出来的评测框架设计大致如下：

- **评测器核心**：冻结的评测器内部职责，外部的一切任务族、架构、指标等研究内容均可插拔。
- **任务族能力矩阵**：从原始数据、任务指标、失败解释、条件控制和研究主张五个层面描述任务族的论证能力。
- **版本谱系**：对机制、接口、任务、判据四类迭代建立独立版本线，以四类版本线冻结为基准，进行条件切换和改进候选谱系生成。

一个评测器模块的开发，工作量感觉几乎要赶上被评测的项目本体了。

与 Coding Agent 的合作也是灾难的，我让 GPT 搭建的第一版评测模块，竟然需要我输十几条参数令人匪夷所思的命令才能跑出一轮实验。做一个可视化评测工作台，呈现的信息量也令人眼花缭乱。厘清自己需要什么边界和向 Agent 澄清自己的边界，又耗费了工作量的八成。

而 RSI 这个研究对象本身仍然存在太多的变数，改进的效果、影响改进效果的因素、改进的适用范围都难以被实验衡量，甚至研究者自己的思路也可能被改进器“改进”。也许我当下能做的，只有为了实验可行性一步步将问题切小，直至看不清那块碎片的价值。

在实验室忙碌许久，日蹬 Token 几个亿，导师过来了解我有什么进展时，我感觉没有什么能直说的，导师也只是让我多读读这个方向的论文。

10 月 24 号，一位师弟问，我这样的人完全可以保研去上交大那样更适合我这个方向的学校（其实我不自信），为什么选择留在了哈工大这个没有具身大脑基础的课题组。我说，因为我确定要做这个方向的时间其实也比较晚了。

我还想过，课题组目前只有我一个人做这个方向，不会太内卷，自由发挥空间还能大一点。

至于这些理由是不是借口，我自己也不知道。
